# Agent Handoff 可见窗口验收发现的缺口

## 发生了什么

2026-09-23，在独立 Con 测试窗口中展开完整交接上下文后，长文本把操作按钮挤出 720px 高的窗口。来源会话下拉框也把长标题放在原生 ID 前，导致准确 ID 被截断。

Codex→Cursor 真实接续成功后，刚创建的 Cursor CLI 会话已有 `~/.cursor/chats` 元数据和 `agent-transcripts` 文本记录，但 Con 的 Cursor 来源列表为空。原生 ACP `session/list` 对该工作目录同样返回空。

## 根因

预览区域只有弹性高度和最小高度，没有上限；GPUI 在长文本布局时仍按内容扩张。会话标签把可变长标题放在固定长度 ID 前。

Cursor 来源适配只读取 ACP 会话列表和回放；该接口并不枚举本次由 Cursor CLI 创建的普通会话。安装能力探测与已有 ACP 会话发现未覆盖这类会话。

## 修复

把 ID 放到会话标题前；预览区域限制最大高度并保持内部滚动。可见窗口中复测完整上下文，底部按钮仍可操作。

Cursor 来源在 ACP 列表之外读取本机 CLI 聊天元数据和已完成 transcript。仅提取 user/assistant 的显式文本，按准确会话 ID 和 canonical cwd 匹配；拒绝未完成的最终 turn，过滤 thought、工具参数与非文本块，保持只读和导出大小上限。用刚创建的真实 Cursor 会话完成发现与预览导出，确认私有 thinking 未进入 `evidence.json`。

## 学到什么

目标能创建并运行原生会话，不代表同一产品的来源接口能找回它。每个目标验收后应立即尝试把新会话反向选作来源；UI 长文本也必须用真实窗口验证，而不只靠布局编译和短 fixture。
