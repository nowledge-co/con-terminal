# Handoff 在同目录有多个会话时要求手选当前会话

## 发生了什么

打开 Handoff 时，即使来源 Codex TUI 正在运行，窗口也只列出该项目的历史会话，用户必须自行判断哪一个属于当前进程。其他本机 Agent 也缺少当前会话绑定。

## 根因

来源 adapter 以工作目录发现可导出的会话，但工作目录并不包含“当前终端进程”的身份。UI 把目录候选列表当成当前会话列表，却没有读取进程持有的锁、启动参数或 Agent 界面提供的原生 ID。Gemini、Copilot 等脚本 CLI 的前台进程组 leader 名为 `node`，旧入口识别还可能把它们当成未知程序。

## 修复

Codex 从前台进程打开的 writer lock 读取 thread ID。其余 Agent 解析前台进程的原生 argv 中明确的 session ID；Kimi 还可从欢迎界面读取 ID。对脚本 CLI，入口识别读取 leader 的 argv 中的脚本路径，避免只看到 `node`。所有证据都必须与当前项目的来源发现结果精确匹配后才能自动选中。启动参数只证明初始会话，需用户确认 TUI 内没有切换；启动参数只表示“继续最近会话”、没有持久化记录或证据冲突时保留手选与确认。准备交接前重新检查绑定。

## 学到什么

“同一目录下最近更新的历史记录”不是正在运行的会话。每个来源产品都需要可验证的进程或界面证据；无法证明时应明确暴露不确定性。
